# How I Built an AI-Ready Project Bundler — Turning Massive Codebases into LLM-Friendly Packages

**8 min read** • [Try It Live](https://treebundle.pages.dev) • Tags: AI, Developer Tools, Code Analysis, GitHub, Productivity

---

## 🚀 WHY I BUILT THIS

Working with large codebases and AI models is often more frustrating than it should be. Every time I wanted an LLM to analyze a project, I found myself manually copying files, removing unnecessary content, splitting huge repositories into manageable chunks, and trying to preserve enough context so the model could actually understand the code.

Most existing solutions focused on either repository visualization or simple file exports. They rarely handled the full workflow of collecting source files, processing documents, organizing structure, and preparing everything for AI consumption in a clean and predictable way.

After repeating the same tedious process across multiple projects, I realized the tooling itself was the bottleneck. I wanted something that could pull code directly from GitHub, process local documents, intelligently split content, and package everything into a format optimized for AI analysis. So I decided to build it myself.

---

## ✨ WHAT IT DOES

TreeBundle is a browser-based tool that gathers source code and documents from multiple sources, organizes them into a structured project bundle, and prepares them for AI analysis. Instead of manually stitching together repositories and files, I can ingest an entire project, preserve its structure, split large content intelligently, and export everything as a clean package ready for code reviews, documentation generation, architecture analysis, or LLM workflows. The entire process happens directly in the browser, keeping the experience fast, private, and easy to use.

## ⚙️ HOW IT WORKS

At its core, TreeBundle collects files from GitHub repositories or local uploads and converts them into a unified project representation. The system analyzes file boundaries, preserves structure, and applies intelligent splitting rules so large projects can be divided into manageable chunks without breaking logical sections of code. This helps maintain context when the output is consumed by AI models.

I chose Cloudflare Workers because they provide a lightweight deployment model with excellent performance. Vanilla JavaScript keeps the application simple and dependency-light, while Tailwind CSS helps create a polished interface without adding unnecessary complexity. Libraries like PDF.js, Mammoth, and JSZip handle document extraction and bundling so the tool can support both code repositories and common document formats in a single workflow.

## 🧩 CHALLENGES I FACED

One of the hardest problems was splitting large projects without destroying context. A simple line-based split would frequently separate related functions, classes, or modules into different files. To solve this, I implemented logic that respects file headers and attempts to identify safer break points around code boundaries, blank lines, and structural markers.

Another challenge was supporting multiple document formats in a unified workflow. Code files are straightforward, but PDFs and DOCX documents require completely different extraction pipelines. I integrated PDF.js for PDF parsing and Mammoth for DOCX processing, then normalized the extracted content into a consistent format before bundling.

Privacy was also a core design requirement. Many developers are uncomfortable uploading repositories or access tokens to third-party services. I addressed this by keeping processing entirely client-side, storing settings locally, and avoiding any backend database. As a result, the application can handle sensitive projects while maintaining a zero-trust approach.
